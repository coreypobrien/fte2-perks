# Working on the AFE2 static perk planner

Read `README.md`, `docs/architecture.md`, `docs/native-chip-rules.md`, and `docs/planner-ui-plan.md` before changing behavior. The user's conversation instructions take precedence.

## Product contract

- Target a static browser application. `app/` contains production UI/module sources; `dist/` is generated. No backend, login, telemetry, hosted saves, or runtime external CDN is required.
- Keep fixed orientations. Do not generate rotations or silently switch a selected ability.
- Required perks are hard constraints; optional requests use strict lexicographic order. More lower-priority perks must not displace a feasible higher-priority one.
- Never automatically add unrequested filler perks. An optional requested core/connector may enable a higher-ranked or required modifier.
- Effects you get contains only equipped requested-perk descriptions, excluding fixed primary/secondary/passive abilities. Conditional bonuses retain conditions. Omitted descriptions appear only Below the line, with their omission reason. Hover/focus links perk rows, grid tiles and descriptions by stable ID.
- Keep requested perks visible when excluded or incompatible. Inclusion checkmarks, grid, descriptions, and omissions must use one solved input snapshot and become stale together after edits.
- Library granting-class filters use unlock metadata independently of equip eligibility. Preserve expanded descriptions across list updates. Keep drag reorder and keyboard arrows using the same autosave/stale-result behavior. New build names start blank.
- Known ordinary-perk grants in the selected class obey its rank. Other-class and unknown/shared unlocks remain assumed available. Alternate selected-class unlock paths use the earliest known qualifying grant; an unknown-rank path is not proof of a lock. Equip restrictions remain independent of origin. Preserve locked requests and report their reason.
- Save locally to browser storage or a portable clipboard/JSON file. Import/export schema is independent of browser storage; validate before changing any input, preserve order/Required flags/unknown IDs, import only into the draft, and recompute layouts. Never overwrite named saves on import. Preserve unknown IDs; do not overwrite malformed/future-version saves during recovery. Named snapshots must not alias autosaved drafts.

## Source data and native research

- Do not edit installed game files or inject tools into the game. Read-only executable/package analysis is authorized; scratch tools and converted game assets belong in ignored `work/`.
- `data/extracted/` preserves explicit serialized observations. `data/native/` provides hash-audited native defaults/rules. `data/perks/catalog.json` resolves footprints. `app/data/game.json` is generated by `node scripts/build-web-data.mjs`.
- Never hand-edit browser data or use `data/verified/` user observations as production overrides. Observations are independent tests only.
- Native recipes reject unknown executable hashes. Updating the expected hash alone is not a patch migration: audit descriptors, instructions, enum values, and affected code paths first.
- Modifiers auto-populate tags from Modifiers[].ModifierTag unless the opt-out flag is true. Matching is directional: modifier tag equals core query or descends from it.
- A modifier belongs to ONE orthogonally connected Core group. Shared-bridge reachability alone is insufficient. Each group permits at most one GrantedAbilityOverride chip, including its Core.
- Use selected ability replacement compatibility, not a union with the base ability. All 29 PerksOld paths remain referenced by current class entitlements; never filter solely by folder name.
- Full ownership/acquisition and all runtime edge cases are not certified. Keep limitations honest; an optimal result is relative to the implemented audited rule model.

## Commands (Node.js 22.14+)

```powershell
pnpm install --frozen-lockfile
pnpm dev                                      # http://127.0.0.1:4173
node scripts/build-web-data.mjs
node scripts/build-static.mjs                 # generates dist/
node --test --experimental-test-coverage tests/*.test.js
node scripts/validate-catalog.mjs
node scripts/test-catalog-inputs.mjs
```

Browser tests use pinned Playwright (`pnpm install --frozen-lockfile`, then `pnpm exec playwright install chromium`) or an existing installation via `--playwright-module PATH_TO_INDEX_MJS`. Pass `--browser-path PATH_TO_BROWSER_EXE` for installed Edge/Chrome. `node scripts/test-browser.mjs --directory dist` owns and cleans up an ephemeral loopback server; `--base-url URL` tests an existing server.

Run affected tests while implementing, then the full unit/catalog/browser suite once final inputs settle. Browser evidence goes to ignored `work/evidence/`. Do not claim unit coverage for DOM code; `main.js` and `worker.js` are verified through real-browser flows.

When changing solver semantics, retain the independent exhaustive small-board oracle and regression tests for fixed orientation, optional connectors, shared bridges, overrides, required conflicts, and budget truthfulness. Do not replace them with implementation-mirroring snapshots.

Keep future-agent documentation current, record tests and limitations, and commit coherent changes using the repository-local Git identity. Do not publish or deploy without a user request.

For solver changes, read docs/solver-performance.md and run scripts/benchmark-solver.mjs. Never treat connectivity failure as geometric impossibility: later requested connectors may repair it. Reachability pruning is a relaxation and must retain fixed modifiers and sparse-footprint safeguards. Occupancy memo keys must preserve connection-bearing identity and footprint masks.

Portable format and rank-filter rules are in docs/build-transfer.md. Retain clipboard success/denial recovery, file round trips, invalid/future input preservation, and imported unknown IDs in browser tests. Five seeded Machinist validation inputs live in examples/machinist-validation; their recorded timeout layouts are best found, not optimality certificates.

Solver UI uses a fixed 60-second wall-time budget (no practical UI node cap), with Find arrangement above and below priorities, a cancellable spinner and elapsed time, and no budget selector. Clear priorities cancels the worker, empties only draft requests, resets displayed results/effects/omissions, autosaves, and leaves named snapshots untouched. Keep progress cleanup tests for completion, cancellation, input edits, clearing and worker errors.

Machinist validation examples must contain only explicit Machinist grants with a known required rank at most 10 and no additional grant condition. Cross-class eligibility or OriginKit alone is insufficient. Fixed abilities may use Machinist class-slot defaults or replacements with rank-appropriate Machinist grants. Retain direct fixture regression assertions.
